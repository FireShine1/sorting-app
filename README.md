# Sorting App

Список из 1 000 000 элементов (ID 1…1 000 000): выбор, фильтрация, добавление новых ID и сортировка выбранных через Drag & Drop.

- **Backend:** Express.js, ES-модули (`server/`), всё хранится в памяти процесса. Node.js 22+.
- **Frontend:** Vue 3 + Vite (`client/`), Drag & Drop на `vuedraggable` (SortableJS).

## Запуск локально

```bash
npm run build 
npm start       # http://localhost:3000
```

## Деплой (Render.com)
Данные живут в памяти и сбрасываются при перезапуске. На бесплатном тарифе Render сервис засыпает после простоя, после чего состояние начинается заново.

## Как устроено

### Хранение
- Элементы 1…1 000 000 не материализуются: существование проверяется по диапазону. Добавленные пользователем ID хранятся в отсортированном массиве и `Set`.
- Выбранные элементы: упорядоченный массив (порядок пользователя) и `Set` для проверок за O(1).
- Состояние общее для всех пользователей. Фильтры хранятся только в компонентах и после перезагрузки сбрасываются.

### API
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/items?filter=&after=&limit=` | невыбранные элементы по возрастанию ID, курсорная пагинация (`after` = последний полученный ID), не больше 20 |
| POST | `/api/items` `{id}` | добавить ID (батч раз в 10 с), `409` если ID уже есть |
| GET | `/api/selected?filter=&offset=&limit=` | выбранные элементы в пользовательском порядке, не больше 20 |
| POST | `/api/selected` `{id}` | выбрать |
| DELETE | `/api/selected/:id` | убрать из выбранных |
| POST | `/api/selected/reorder` `{id, targetId, position}` | поставить `id` перед или после `targetId` |
| POST | `/api/batch` `{ops:[{op, ...}]}` | несколько операций (`items`, `selected`, `select`, `deselect`, `reorder`) одним запросом |
| GET | `/api/stats` | счётчики очередей (принято, схлопнуто, батчи) |

### Очередь, дедупликация, батчинг (`server/src/queue/BatchQueue.js`)
- Каждая операция ставится в очередь, HTTP-запрос ждёт ближайшей обработки очереди.
- **Чтение и изменение** (`items`, `selected`, `select`, `deselect`, `reorder`) обрабатываются одним батчем раз в **1 с**. Записи применяются строго в порядке поступления, затем выполняются чтения по уже обновлённому состоянию.
- **Добавление** обрабатывается батчем раз в **10 с**.
- **Дедупликация:** одинаковые операции внутри одного батча схлопываются: работа выполняется один раз, результат получают все вызывающие. Запись схлопывается только с последней записью по той же сущности, поэтому «выбрать 5, снять 5, выбрать 5» остаются тремя операциями.
- **Гарантия уникальности ID:** очередь — единственный писатель, а проверка и вставка выполняются вместе внутри синхронной обработки батча (`Store.add` возвращает `false`, если ID уже есть). Уже существующий ID отклоняется сразу, без ожидания батча. Одинаковые добавления в одном батче схлопываются.

На клиенте (`client/src/api/batchClient.js`) тоже есть очередь: операции копятся и уходят одним `POST /api/batch`, одновременно в полёте не больше одного запроса, одинаковые чтения не дублируются.
